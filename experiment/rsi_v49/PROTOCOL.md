## Serial native semantics

A body is a sequence of native content-address transformations of UTF-8 text:
SQLite HEX, regex run-length encoding, JSON string encoding and zlib encoding.
Each step SHA-256 addresses the transformed bytes. The next step receives that
address as its input. These are real serial dependencies; there are no independent
answer slots and no partial coordinate oracle. The fixed four-kernel vocabulary,
content-address reduction and host-authored curriculum/scheduler remain limits.

References independently construct hexadecimal, runs and JSON quoting; compression
uses the same externally maintained zlib via a separate compressor API. This is
project-authored evaluation, not independent replication. Fingerprints use four
fixed diagnostic texts; equality is only observational on those texts, with the
usual finite hash-space limitation. Source identity is kept separately.

An execution includes four task contexts and four diagnostic contexts, with actual
native primitive visits and transformed UTF-8 byte counts. Every requested body,
screen, failed candidate and exact confirmation costs one call. Fingerprint work
is included in that call. Construction never predicts candidate outputs and sees
only paid whole-pipeline scalar correctness and public source/donor identities.
Candidates receive inputs only, never targets or expected answers. Fixed native
worker CPU/memory/time limits are inherited unchanged; instrument failures are
retained and never retried for free.

## Acquisition and equal governance

Epoch zero has four one-step targets. Each next epoch samples four distinct source
sequences by joining two of the preceding epoch's four sequences; no behavior,
distance, solvability or observation filters sampling. Interface length doubles.
Four input families use punctuation, Unicode, JSON texts and base64 texts. They
are input families of one cross-stack pipeline substrate, not four new independent
L7 qualifications. Two repeats of each target are shuffled without branch labels.

All arms have 26 candidate calls per task. Pay identity and at most four archive
screens. Search uses deterministic lexical products of admitted whole-program
tools, leaving one call for exact confirmation. Archive admits previously successful
whole bodies of half the current length. Archive-ancestor admits quarter-length
whole bodies, removing the latest acquisition and composing four instead of two.
Greedy admits only its latest successful body's tools, without substring extraction;
cold uses only the initial four one-step kernels. Whole-body retrieval is identical
for archive and ancestor. Every donor must have succeeded strictly before its
current use; record its exact acquisition position and source ancestry.

No G7 call or newly qualified G8 policy is claimed. All proposed bodies, including
budget-truncated failures, remain in the journal. A new discovery is a successfully
solved diagnostic behavior absent from *every* prior evaluated source, including
failures. Also report first-solving behavior ignoring failed observations separately.
No syntactic size increase substitutes for behavioral novelty.

## Continuation boundary

Given all four prior successful tools, sixteen two-tool products suffice to find
any next target; root, four screens and confirmation give at most 22 calls. This
is conditional constructibility, not a proof of indefinitely novel behaviors.
Native visits grow with pipeline length; positive discovery/call does not imply
a positive lower bound per native work unit. SHA-256's finite range, diagnostic
witnesses, fixed primitive kernels, closed composition curriculum and fixed worker
resources prohibit claiming general open-ended L9 from this assay. L9/L10 and new
policy-generation flags stay false even if this scoped coupled-native test passes.
