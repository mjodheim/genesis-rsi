## Codec semantics and exact identity

Four encoders act on nonempty UTF-8 text: actual SQLite uppercase hexadecimal,
actual regex run-length encoding (count:ordinal;), actual JSON string quoting,
and actual gzip followed by base64. Gzip has canonical OS=255 and mtime=0.
Each encoder is injective; their output languages are pairwise disjoint. The
fixture base texts begin with a seedling Unicode character, outside all four
output languages. Repeatedly classifying and inversely decoding actual outputs
recovers the exact full operator word and base input. No step hashes its output.
SHA-256 protects source/transport provenance but never defines semantic equality.

The mathematical model idealizes the format specifications as total encoders on
arbitrarily long finite strings. It therefore has an unbounded exact behavior space
indexed by unhashed finite codec words. Actual native libraries have operand-size
limits as well as the worker's resource limits; the model is not a claim that those
implementations execute every model word. It establishes neither arbitrary-program
semantic equivalence nor native infinite execution.

## Public engineering population

Collect the identity and every operator word of lengths one through four: 341
programs. Each candidate runs in the inherited isolated worker on the four exact
public texts declared in native.py. Execute each twice, charging and reserving
two calls before behavior: 682 calls total, no selection, resampling or retry.
Record complete native outputs, source identity, inverse-decoded word, actual
primitive visits and encoder input/output interface bytes. Final zlib/base64 output
compression is transport only; it adds work not counted as codec primitive visits.
Decoded transport has a fixed 2 MiB guard; the inherited CPU/memory/time limits
remain unchanged. Any instrument failure consumes the full reservation and is
preserved as failed or pending, with its visit upper bound; it is never free.

Commit all apparatus, public fixture declarations, tests and this review before

Passing requires all 341 public programs to match their independent references,
decode exactly to the known word/base text, and repeat exactly. The result is
development_validated only. This collects no fresh holdout, selects no recursive

## Conditional archive continuation

If four equal-length successful whole programs survive, sixteen pairwise
compositions include every next target built from two of those tools. Exact
external whole-output feedback is equivalent to word equality in this model.
Identity, up to four screens, sixteen proposals and confirmation cost at most
22 calls within a 26-call cap. The first task at each strictly larger level has
at least one new behavior relative to every earlier-level observation. With eight
tasks per level, discovery/charged-call has conditional lower bound 1/(8*26).
Later successful programs provide the next tools. This is an induction, not an
inference of indefinite novelty from the finite public fixture record.

The model assumes complete retention, the closed two-tool curriculum and total
specification-level encoders with exact feedback. Actual native/library limits
prevent simply transferring this premise to unlimited execution. Source length
and native work grow, and some encoded outputs grow much faster. There is no
positive native-work floor or fixed-hardware infinite continuation claim. A future
archive assay must separately freeze task diversity, resource/work accounting,
matched causal controls and fresh chronology. These limits cannot be removed by
renaming this engineering record a completed general L9 result.
