# V33 — prospective consumed-data multi-probe development

Declared before this successor's first behavioral execution on 4 October 2026.
This is DEVELOPMENT, Track B, on already consumed data. No canonical attempt,
fresh scientific population, acquired G8, L9 or L10 pass is asserted.

V32 measured scalar compatibility and retained a negative adaptive criterion.
This successor asks whether a small measured behavioral fingerprint reduces
harmful memory retrieval. The fingerprint consists of revealed qualities for
identity, XOR of bit zero, and rotation by one. The evaluator alone owns inputs
and expected outputs. The controller receives only its existing three integer
diagnostics; no task name, family, target or input/output pair is sent to it.

Exactly four arms: `probe` uses G7 and nearest three-quality Manhattan distance
<=75; `scalar` uses G7 and nearest identity-quality distance <=25;
`probe_ablation` uses exact G6's absent selector and always retrieves the nearest
two by the three-quality distance; `cold` always generates from the root.
Every arm performs the same three probes and one controller call, plus at most
ten candidate evaluations, eight rounds, parallelism two and depth three.
Maximum charged cost is fourteen per task. All search sources remain exact G7.
The thresholds are fixed development hypotheses, not tuned on these outcomes.

Rank previously successful sources of the same width by minimum distance to a
fingerprint from a past task on which they actually solved, then recency, success
count and source digest. Store every evaluated descendant, including negatives.
All candidates are re-evaluated at full cost. The probes are additional charged
evaluations even if search subsequently evaluates the same source.

Run all 240 consumed V31 tasks (five seeds) and all 216 consumed V32 tasks (three
seeds), all four arms, unchanged order, with no outcome-based omissions. Begin
each seed/arm with empty history. Preserve interrupted journals and reserve the
whole fourteen-call budget before a task; never retry a pending task for free.
Resume only at completed task boundaries. Bind the apparatus digest, complete
stream, arm and execution mode to each journal. Reconstruct histories from disk.

Report per seed/arm/window: coverage, charged cost, archive size, newly observed
solving sources, rediscovery and observed worse-than-root retrievals. Distinguish
proposed retrieval from actually evaluated retrieval. Report paired coverage
against every control. A descriptive finite success requires more total solves
than every control, no greater cost than cold and no per-stream loss against
cold. It is always DEVELOPMENT evidence; failure does not license replacing
this protocol or its results.

The fast sweep uses non-isolated, project-controlled pure transforms and is
explicitly labelled accordingly. Isolated worker execution and exact receipt
replay are tested separately on consumed fixtures. Neither is independence.
No fresh-bank or qualification command is provided.

L9's next apparatus still needs genuinely diverse domain adapters and a sustained
prospective stream, with immutable epoch commitments, full failed evaluations,
equal-budget archive/greedy/cold controls, descendant diversity and rate
trajectories. A finite rate or a larger width interval cannot settle open-endedness.
