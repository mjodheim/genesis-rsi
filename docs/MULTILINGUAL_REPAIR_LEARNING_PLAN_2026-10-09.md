# Progressive multilingual repair learning

Status: prospective development design, not an executed experiment or a sealed task protocol. Requested by Anthony on 9 October 2026; prepared with OpenAI Codex assistance. No new core mechanism, third-party task contents or held-out results are disclosed here. Existing adaptive-repair publication and scientific boundaries apply.

## Objective and current boundary

Measure whether accumulated experience increases autonomous repair of different bugs, including transfer across languages. The current development service retains validated exact-text edits and chooses existing local operators; its real-project validation harness uses Java/Defects4J. It does not yet demonstrate autonomous invention of new operators. Memory replay, new combinations of existing operators and new operators are separate outcomes.

## Curriculum

Start with Java, Python and JavaScript. Use comparable families such as missing initialization, boundary conditions, null/missing values, incorrect state updates and input validation. Select tasks and budgets before observing repairs. Include real released development bugs; label project-authored exercises separately and never use them as evidence of independent real-world generality. Review task licences and provenance before admitting external content.

Use three successive batches, initially targeting five training bugs per language per batch. This is a design target, not a populated task bank. Expand only after runners and validation are reliable. Retain all failed attempts. Use fixed API and candidate-validation budgets for comparable tasks; propose a maximum of $0.05 per training task, including failed requests. Unknown charges remain unknown and stop paid escalation.

## Controlled measurement

Before training, select a separate evaluation bank and freeze task identities, tests, budgets and baseline code. Keep evaluation source and repair outcomes out of training. Do not use previously exposed Genesis cases as unseen evidence or consume reserved scientific benchmarks.

After each batch, snapshot learned memory and policy. Evaluate with no external model calls and no persistent learning during evaluation. Compare the same task conditions against the initial memory and the initial operator policy. Keep evaluation outcomes inaccessible to subsequent training and task selection; use a separate final unseen bank to check the resulting policy. Public bug provenance cannot exclude prior model training contamination.

Report by language and bug family: suite passes/attempts, zero-model passes, candidate validations, wall time, known API cost including failures, unknown charges, and cost per passing repair. Record how each candidate was produced:

- exact-context replay of a retained transformation;
- adaptation or composition of existing transformations/operators;
- newly generated executable repair rule.

Cross-language transfer requires paired evidence from related semantic tasks with distinct syntax; an increased aggregate score alone is insufficient.

## Learning and invention admission

For each training success, retain the patch, symptom, applicable source context, producer, validation evidence and costs. Revalidate persisted experience from a new process. Failed repairs must not be admitted as successful recipes. Explanations are hypotheses unless supported by executable checks.

A future rule-generation stage must record the generating component and whether an external LLM assisted. A rule proposed by an external LLM is assisted learning. A rule generated by Genesis without such a call may count as endogenous rule generation only after its executable behavior differs from the existing rule inventory and it succeeds on separately selected related tasks. Novelty of the patch text alone is insufficient. Full test-suite success establishes test adequacy, not proof of semantic correctness or general intelligence.

Generated rules must run in an isolated executor with bounded resources and no network or host privileges. They must not alter validators or their own evaluation tests. Admission requires independent validation and regression checks; preserve rejected rules and reasons.
