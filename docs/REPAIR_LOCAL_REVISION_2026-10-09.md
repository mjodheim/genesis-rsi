# Single-component repair configuration pilot — 9 October 2026

General RSI remains the objective, not an achieved result. Earlier LINEAGE1's
promoted configuration did not transfer on its held-out comparison. Corrected
LINEAGE2 rejected all four successors, each worse than its parent. Old evidence
and held-out boundaries are unchanged by this work.

## Diagnosis and revised proposal mechanism

Relative to LINEAGE2's seed, the four rejected proposals changed respectively
3, 4, 4 and 6 genome leaves. These changes included instructions, playbook,
improver, system and/or evidence controls. That is a structural observation,
not proof that changing several leaves caused their poorer scores.

The new `repair_local_revision.propose` asks the same approved economical external
model to alter exactly one allowed leaf. System and improver remain fixed. The
host verifies the constraint, preserves offending proposals and their charges,
and declines unchanged or multi-leaf proposals. Human-authored mutation boundaries
are explicit. A text leaf can still contain several semantic changes; the mechanism
does not isolate each sentence's causal effect or invent new repair primitives.

The model reads only the seed's first-replicate training report from LINEAGE2.
Selection outcomes are not supplied to the proposer. It chose the instructions
leaf, adding earlier candidate submission, bounded inspections and more specific
read arguments. This is externally assisted configuration revision, not learned
model weights, no-LLM repair or improvement of the improver itself.

One caveat is already visible before measurement: the proposed text mentions an
optional `end` argument for `read_file`, whose actual schema only has `path` and
`start`. Structural genome acceptance does not ensure accurate tool semantics.
The historical runner and tool schema are kept intact; this discrepancy is not
silently corrected after observing the proposal.

## Fixed development pilot

`DEV_REPAIR_LOCAL_REVISION1/PLAN.json` was committed before execution. Cases are
the first three selection cases in LINEAGE2's order: Mockito-17, Jsoup-54,
Mockito-23. They are previously exposed development bugs; none is fresh or held-out.
The proposer sees none of these case outcomes in this pilot.

Parent and child each receive two newly executed evaluations per case, six candidate
validations and eight model requests per case, 4096 output tokens/request. Execution
order alternates across case and replicate. The separate successor request can use
6000 output tokens. Global ceiling USD 0.35, with provider tariff caps checked before
freezing: Haiku prompt at most USD 0.2/million, completion at most USD 1/million.
Every arm's calls and verdicts are stored. Unknown charges remain unknown.

Buggy revisions only are used. The existing corrected apparatus distinguishes
Defects4J triggers from tests already failing on the unmodified buggy revision.
The same tolerated baseline failures apply to both arms. Success is suite plausibility
under that boundary, not semantic correctness. Validation occurs in existing isolated
Docker containers; recipes never modify tests. Source restoration is checked separately.

A strict gain without paired losses only warrants a larger development test.
No outcome of this small pilot promotes a policy or establishes statistical
significance, transfer, meta-improvement or general recursive self-improvement.
Stored-record audit checks ancestry, one-leaf constraint, pairing/order, budget,
receipts and arithmetic. It reruns no repairs and is not independent replication.

## Recorded result

Both arms repair Mockito-17 and Jsoup-54 in both repetitions. Neither repairs
Mockito-23 in either repetition. Thus **4/6 case runs for each arm**, zero paired
gains, zero paired losses. This does not warrant a larger test of this particular
proposal under the frozen exploratory rule. No policy is promoted.

Successor writing adds one request, USD 0.00181330. Total **38 requests,
USD 0.04255552**, zero new unknown charges. Runtime/compilation and developer costs
are excluded; the small API difference is not evidence of a total-cost gain.

The first parent run on Mockito-23 submits one inapplicable edit and stops with
zero validations although its request envelope remains. The descendant instead
validates three then four applicable candidates across repetitions; all seven
compile but fail triggers. It reaches the round limit without repair. Better
edit applicability has not produced a successful behavioural hypothesis. The
existing proposer returns immediately after a submission, and `run_arm` stops
when the round has no fresh candidate; this is an apparatus-level opportunity
for a separately frozen bounded retry experiment, not grounds to alter this score.

All three tracked buggy checkouts are restored. Canonical recipe memory remains
292 events; this pilot's configurations, calls, failures and plausible patches
are archived in the trial, without claiming model-free recall or policy adoption.
The preserved negative evidence informs the next step: explicit proposal/application
failure feedback within the same request budget, then transferable repair-language
capabilities. Rewriting a text field alone has not demonstrated general improvement.

31 focused tests pass, including refusal of false successes, over-budget records
and invalid/multi-leaf revisions. Repository integrity checks pass. The stored audit
is not an independent execution replication or a semantic correctness proof.
