# Repair-transformation learning — prospective development, 9 October 2026

Anthony authorised implementing reusable learning and then three new trials.
OpenAI Codex provides development assistance. The substrate is authored;
model-origin repairs remain attributed and are not endogenous inventions.

## Implemented behaviour

`genesis.repair_transformation_learning.acquire` extracts bounded Java lexical
replacement templates from sealed, full-suite-passing released recipes. Shared
variable identifiers become consistent bindings; member/API names, classes,
keywords and literal values remain fixed. Templates preserve their recipe,
candidate, verdict and model-origin provenance. Unsupported or constant-only
changes stay exact recipes. This is lexical structure, not a full Java AST,
type inference, causal understanding or an invented primitive.

Generation changes only production Java near observed failures. It refuses
symlinks, tests and unsupported lexical input; comments/strings are not treated
as code. Introduced API names must occur in a bounded production-symbol
inventory. Existence is not a type guarantee; every proposal requires compilation,
triggering tests and the full suite. Behavioural counterexamples are necessary:
a length inequality correction can be wrong where exact length is required.

A bounded feedback controller avoids duplicate attempts and reprioritises
hypotheses using its own compiler and test feedback. It does not infer a repair
from assertion text. The adaptive service exposes explicit `transformation_policy`,
`local_feedback_rounds` and `learn_transformation_proposals` options; its default
behaviour is preserved. New successful recipes can propose a next-generation
policy, but only a separate controller may promote it.

## Frozen experiment

[PLAN](../experiment/bench/DEV_REPAIR_TRANSFORMATION_TRANSFER1/PLAN.json) selects
**Jsoup-59, Math-41 and Compress-44** before opening their sources: first remaining
case per project in the immutable development order, excluding a conservative
census of prior public development results. No fixed revision or reserved case
is inspected. Cases remain public Java DEVELOPMENT, not independent blind tasks.

The initial canonical 124-event memory teaches three rules across three acquisition
generations: outer-owner qualification, a whitespace call wrapper and a length
comparison. These operations were derived from assisted successes, not generated
without model help originally. Each generation is selected against authored,
renamed/reformatted Java positives and behavioural counterexamples. These fixtures
are a substrate check, not new real-world evidence or proof of recursive gains.

The real parent uses exact memory plus 32 existing strategist proposals in fixed
order. The child uses the same memory/strategist pool plus learned transformations
and feedback. Each gets at most eight candidate validations per bug, with identical
180-second command ceilings and a pinned isolated image. Model calls are disabled.
Multiple factors change together: any gain would establish a combined change,
not isolate abstraction from feedback. Real promotion requires a strictly larger
solved-case set, no solved-case regression and no increase in aggregate validation
count. Time is recorded; API cost zero does not mean infrastructure cost zero.

Only after all three comparisons can successful repairs enter the cloned memory
and receive fresh-reader full-suite replay. Every failure and policy rejection
is retained. Actual canonical adoption requires evidence audit and preservation
of the complete initial memory prefix. Three real cases cannot establish general
RSI, multilingual generality, multi-edit synthesis or recursive acceleration.

rewrites the protocol. The audit checks stored evidence; it is not independent
execution replication. Results will be appended after execution.

## Observed results

The preregistered code and protocol were committed and pushed before execution.
All three real cases completed without interruption or external model calls.

| Public Java development case | Parent solved / child solved | Parent compile failures / child compile failures | Learned candidates |
|---|---|---|---:|
| Jsoup-59 | no / no | 2/8 / 4/8 | 0 |
| Math-41 | no / no | 8/8 / 8/8 | 0 |
| Compress-44 | no / no | 6/8 / 6/8 | 0 |

There were **0/3 successes in each arm**, 24 candidate validations per arm,
**34 compilation failures out of 48 validations**, and no gain. The policy was
not promoted. The feedback controller changed the attempted order only for
Jsoup; Math and Compress used identical sequences. Its behavioural-hypothesis
labels are limited by the existing strategist adapter: all local descriptions
say `repair_plan`, hiding component-operator provenance. Jsoup's child had more
compilation failures. A shorter run time is not evidence of better repair.

No learned rule produced a candidate in these causal source views. Thus the
trial supplies no positive or negative measurement of those rules' repair
efficacy on applicable real bugs; it shows that their current structural forms
and bounded focus do not cover this selected set. It does not establish absence
of solutions in every larger generator configuration. The module remains an
explicit opt-in experimental capability, not the default active repair policy.

The three authored acquisition generations passed: 2, 4 and 6 positive transfers
respectively, with no accepted negative controls. This demonstrates identifier/
layout transfer within the authored forms and rejection by executable behavioural
tests, not learned semantic preconditions, autonomous primitive invention or
recursive acceleration. Guards remain syntactic plus mandatory validation.

There is no new successful repair or success replay to claim. All 48 failed
validations and the rule/decision receipt entered the canonical development
memory as a verified 49-event suffix: **124 → 173 events**, with all prior
successes, failures and unknown historical charges preserved. Proposed capabilities
and failures can be inspected by future invocations; they are not promoted policy.
New API requests/cost: **0 / $0**. Runtime infrastructure and development are excluded.
