# A6 prospective decreasing-fallback campaign — 2026-10-06

**Development verdict: FAIL — informative prospective result**

A6 was pre-registered to test whether external-model fallback demand decreases
as Genesis accumulates evaluated repair experience.

The campaign completed **12 runnable external/public tasks** in three frozen
waves of four. Results were not replaced after outcome.

## Why A6 failed

The result is useful because it exposes a concrete architectural failure rather
than an ambiguous lack of compute.

### 1. Memory candidates starved generic candidates

The A6 runner prepended all learned-template, retained-strategy and repository
exemplar candidates before generic scalar candidates.

On task 9, the exact useful comparison-boundary repair was already generated
with zero LLM calls. It was:

- scalar-family rank: **73**
- mixed candidate-pool rank: **524**
- frozen execution budget: **256**

So Genesis possessed the correct candidate but never evaluated it. More memory
made the search order worse.

### 2. The runner was single-site

Task 10 required the same comparison-boundary correction at two independent
sites. The frozen A6 runner evaluated one mutation candidate at a time and could
not compose the two individually expressible edits into one candidate.

### 3. Later tasks needed structural transformations

Tasks 11 and 12 required transformations outside the current generic scalar
grammar, including expression restructuring and coordinated multi-line edits.

## Interpretation

A6 therefore does **not** support the claim that model dependence is currently
decreasing. The opposite occurred in this campaign:

`fallback rate: 0.50 -> 0.75 -> 1.00`

This is retained as a negative result. It must not be relabelled or repaired
post hoc.

The next experiment is **A6b**, which may prospectively change the architecture
to address the failure mechanisms discovered here:

1. target-aware memory candidate generation;
2. fair/stratified candidate scheduling so one generator cannot starve another;
3. bounded coordinated multi-site candidate composition;
4. empirical support/causal-use tracking for retained templates.

A6b must use fresh external tasks for evidence. Retrospective A6 replays may be
used only as development calibration.

A7 remains blocked until a prospective campaign first demonstrates a credible
reduction in fallback dependence.
