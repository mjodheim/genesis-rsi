# Failed-search recovery — 9 October 2026

The frozen quality transfer remains 0/3 in both arms. This work revisits its three
already exposed failures as engineering cases, not independent or fresh transfer.

## Why descendants stopped

The old repair capability lineage accepts a new subscript-offset strategy only
from a successful released-training receipt; a repeated offset is rejected as no
new capability. That boundary protects success attribution, but is not a general
failure-driven improvement controller. The strategist offers a fixed pool once
and returns nothing when passed history. Quality search stops at an empty pool
or its validation limit. Lexical acquisition requires verified replacement blocks
and cannot represent arbitrary insertions or algorithms. A zero pool, exhausted
pool and exhausted budget previously had no distinct terminal diagnosis.

Jsoup-25 additionally lacked production stack frames. The opt-in assertion API
localiser supplies source hypotheses, without interpreting expected literals or
claiming runtime coverage. Its earlier smoke generated candidates, not repairs.

## Adaptation

`repair_stall_recovery.recover` records a sealed generation proposal, parent
proposal digest, previous verdicts and new candidate count. Failed generations can
produce another proposal without first claiming a successful capability. Every
candidate is compiled and tested through the existing isolated validator. Ranking
uses the attempted generation's failure history, deduplication spans generations,
and full-suite regressions are rejected. Nothing automatically promotes a policy.

The engineering schedule is fixed before execution: candidate pools 2/8/32,
twelve total local validations per case, then at most two approved economical
models, two rounds per model, eight assisted validations and USD 0.05 per case.
This authored expansion schedule changes search breadth, not the mutation grammar.
It cannot invent an absent repair operator. The explicit CLI option
`--recover-stalls` exposes the same bounded local controller and persists its
failed attempts before model assistance. `--localize-assertions` is separate.

The three cases are Jsoup-25, Math-37 and Compress-18. All local failures are kept.
Successful recipes must be reloaded by a new memory reader and revalidated against
the full suite. Assisted repairs retain their model attribution. Costs include
failed calls; runtime infrastructure and developer time are excluded. Historical
unknown bills stay unknown. Results and memory admission are recorded separately.

Stored-record audit verifies lineage, budgets, recipe retention and replay receipts;
it is not an independent execution replication. Perfect performance on these three
exposed cases, if achieved, is only this finite endpoint and establishes no general RSI.

## Recorded outcome

All three exposed cases passed full-suite validation and fresh-reader replay with
assistance. Local-only recovery remains **0/3**, after 36 candidate validations.
Each local search produced three generations (2, then 6, then 24 new candidates),
stopping at its total validation cap, not an unexplained disappearance.

Total known API cost: **USD 0.01377242**, including unsuccessful model attempts.
All new API charges are known. Teacher origin and replay receipts are retained
in `experiment/bench/DEV_REPAIR_STALL_RECOVERY1`. The canonical memory grows from
223 to 292 events, preserving the old prefix, all 36 local failures, nine generation
proposals, model calls and three new verified recipes. No search policy is promoted.

Frozen machinery is archived in the runtime workspace and its source corresponds
to commit `11786853`; public audit can check matching source hashes when that
snapshot is unavailable. The audit is read-only for the public JSON export.
The three buggy checkouts have no tracked diff after validation and replay.

This achieves the defined finite assisted-repair endpoint. It does not achieve
perfect autonomous repair, new grammar synthesis or general recursive improvement.
The next substantive deficit is repair-language coverage and transferable guards;
merely increasing the same pool has now been tested and found insufficient here.
